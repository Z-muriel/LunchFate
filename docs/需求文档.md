## 1. 背景与目标

每天中午最难的问题是"吃什么"。团队在几家固定的午餐店铺之间反复纠结，浪费时间。

**LunchFate** 提供一个页面：

1. 维护一份可维护的**午餐店铺清单**（增删改查）；
2. 首页一个**大转盘**，点击即可为"中午吃什么"做出随机抽取，杜绝选择困难。

**目标**

- P0：店铺清单可管理，转盘可抽取，全流程可用。
- 不做：订餐、支付、外卖对接、店铺评价体系（后续迭代再议）。

**成功标准**

- 维护 10 家店铺 ≤ 2 分钟；从打开首页到得到结果 ≤ 10 秒。

## 2. 用户与角色

| 角色 | 说明 | 可访问功能 |
| --- | --- | --- |
| 登录用户 | 普通同事，必须先登录 | 主页转盘 + 本人抽取记录 + 本人门店添加记录；门店操作须另外授权 |
| 管理员 / 获授权用户 | 维护门店和用户权限的人 | 按授权访问门店管理、权限管理；获对应“查看全部记录”权限后可查看当前租户全部记录 |

> 访客不能使用转盘、附近门店搜索或记录查询；页面跳转登录，业务接口拒绝匿名访问。

> 权限按 ABP 权限体系实现（`LunchFate.Shops.*`），默认授予管理员角色。

## 3. 功能需求

### 3.1 主页 · 午餐大转盘（FR-WHEEL）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-W-01 | 主页路由 `/` 展示一个圆形转盘，扇区内容为**已启用**的店铺名称 | P0 |
| FR-W-02 | 中心有"开始"按钮，点击后转盘旋转，动画时长 4~6 秒，减速停止 | P0 |
| FR-W-03 | 指针最终指向的扇区即为抽中结果，弹窗展示店铺名称、分类、人均、地址 | P0 |
| FR-W-04 | 抽取规则：**等概率**随机（所有启用店铺权重相同） | P0 |
| FR-W-05 | 结果弹窗提供"就吃这家 ✅"（关闭）与"再来一次 🔄"（重新抽取） | P0 |
| FR-W-06 | 无任何启用店铺时，转盘区显示空状态插画 + "去添加店铺"引导按钮 | P0 |
| FR-W-07 | 不设置参与转盘的门店数量上限；返回全部启用门店，不截断候选。数量较多时保留完整名称提示，不影响等概率抽取 | P0 |
| FR-W-08 | 店铺可设置**抽取权重**，抽取按权重概率分布 | P1 |
| FR-W-09 | 服务端等概率抽取并持久化记录，保存时间、操作者、门店信息快照及来源；临时附近门店同样记录，未成功保存不得展示为抽取成功 | P0 |
| FR-W-10 | 可开启"避开今天已抽中的店铺" | P1 |
| FR-W-11 | 分享结果（生成图片/文案） | P2 |
| FR-W-12 | 转盘候选 = 门店库启用门店 ∪ 已加入的附近门店，两者可同时参与一次抽取；候选顺序固定为"门店库在前、附近在后"，服务端返回的获胜索引直接对应扇区顺序 | P0 |
| FR-W-13 | 附近搜索的"加入本次转盘"为**追加**语义：多次加入按 POI 标识去重并持续累加，不清空已有候选；提供"清空附近候选"回到纯门店库候选 | P0 |
| FR-W-14 | 附近搜索支持分页，页码/每页条数与结果总数必须准确；服务端返回真实匹配总数，前端据此计算总页数并正确启用/禁用翻页按钮 | P0 |
| FR-W-15 | 附近搜索中心支持"使用当前位置"（浏览器定位）、"设为默认位置"（浏览器本地保存）与"恢复默认位置"（清除本地覆盖、回到服务端配置）；服务端配置项为 `Integration:Gaode:Default*` | P1 |

**交互细节（P0）**

- 转盘由 CSS transform + transition 实现；单次旋转 5~8 圈 + 目标偏移角，缓动 `cubic-bezier(0.15, 0.6, 0.2, 1)`。
- 旋转期间按钮置为禁用（防连点）。
- 扇区超过 8 个时，扇区文字自动缩略（截断 + `title` 提示完整名称）。
- 移动端（≤768px）转盘直径随视口自适应，弹窗改为底部抽屉。

### 3.2 权限与记录管理（FR-AUTH、FR-RECORD）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-A-01 | 所有业务功能必须登录使用，访客不能进行抽取、附近搜索或记录查询 | P0 |
| FR-A-02 | 增加权限管理入口，复用 ABP 用户管理及权限弹窗；管理入口须同时具备用户查看与管理用户权限的授权 | P0 |
| FR-A-03 | 可为其他用户分别分配店铺查看、新增、编辑、删除权限；新增须同时具备查看和新增权限 | P0 |
| FR-R-01 | 两类记录页面默认只显示当前用户在当前租户的记录；查看全部须分别授予对应权限，宿主 null 与各租户严格隔离 | P0 |
| FR-R-02 | 抽取记录保存门店名称、地址、分类、人均、时间、操作者及永久/临时来源快照；临时 POI 保留标识且不伪造库门店 Id | P0 |
| FR-R-03 | 门店单条、批量成功新增时，通过同一工作单元的本地事件保存添加记录；失败或跳过不生成成功记录 | P0 |
| FR-R-04 | 两类记录支持关键字（门店/操作者/地址）、日期范围筛选及每页 20 条分页，默认按时间降序；历史在门店改名、删除后保留，不提供编辑删除端点 | P0 |
| FR-R-05 | 新功能启用后产生记录；不补造此前抽取历史或门店添加历史 | P0 |

### 3.3 店铺管理 · 增删改查（FR-SHOP）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-S-01 | **查**：列表分页展示，支持关键字（名称/标签）、分类、启用状态筛选；列含名称、分类、人均、评分、状态、更新时间 | P0 |
| FR-S-02 | **增**：弹窗表单新增店铺，必填校验 | P0 |
| FR-S-03 | **改**：点击行内"编辑"打开同一弹窗，回填数据并保存 | P0 |
| FR-S-04 | **删**：删除前二次确认，提示"确定删除店铺『xxx』？"；采用软删除，数据可恢复 | P0 |
| FR-S-05 | **启/停用**：停用后不进入转盘，但保留在列表中 | P0 |
| FR-S-06 | 详情抽屉：展示完整信息（含备注、标签、创建/更新时间） | P1 |
| FR-S-07 | 导出 Excel | P2 |

**校验规则**

| 字段 | 必填 | 约束 |

| 店铺名称 | ✅ | ≤ 64 字符，同名（未删除）唯一 |
| 分类 | ✅ | 枚举：快餐 / 盖饭 / 面食 / 米粉 / 日料 / 西餐 / 轻食 / 饮品 / 其他 |
| 人均价格 | — | ≥ 0，保留 2 位小数 |
| 地址 | — | ≤ 256 字符 |
| 电话 | — | ≤ 32 字符 |
| 评分 | — | 1.0 ~ 5.0，0.5 步进 |
| 标签 | — | ≤ 5 个，逗号分隔，单个 ≤ 12 字符 |
| 抽取权重（P1） | — | 1 ~ 100，默认 1 |
| 是否启用 | — | 默认启用 |
| 备注 | — | ≤ 512 字符 |

## 5. 数据模型

表名前缀沿用工程约定 `LunchFateConsts.DbTablePrefix = "App"` → **`AppShops`**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Id | uniqueidentifier | PK |
| Name | nvarchar(64) | 店铺名称，必填、唯一 |
| Category | int | 分类枚举 `ShopCategory` |
| Address | nvarchar(256) | 地址 |
| Phone | nvarchar(32) | 联系电话 |
| AveragePrice | decimal(18,2) | 人均价格 |
| Rating | decimal(3,1) | 评分 1.0~5.0 |
| Tags | nvarchar(256) | 标签，逗号分隔 |
| Weight | int | 抽取权重，默认 1（P1 生效） |
| IsEnabled | bit | 是否启用，默认 1 |
| Remark | nvarchar(512) | 备注 |
| ExtraProperties | nvarchar(max) | ABP 扩展字段 |
| ConcurrencyStamp | nvarchar(40) | ABP 并发戳 |
| IsDeleted | bit | ABP 软删除 |
| CreatorId / CreationTime / LastModifierId / LastModificationTime | — | ABP 审计字段 |

追加独立表 **`AppDrawRecords`** 与 **`AppShopCreationRecords`**：`Id, TenantId, UserId, UserName, ShopId, ShopName, Address, Category, AveragePrice, RecordTime`，沿用聚合根扩展字段和并发戳。

抽取表另有 `IsTemporary, PoiId`；临时门店 `ShopId = null`。两表不对门店或用户建立外键，保留不可变快照，建立 `(TenantId, UserId, RecordTime)` 与 `(TenantId, RecordTime)` 索引。查询显式约束当前租户（含宿主 null），即使框架多租户过滤关闭也不能跨边界。现有门店库的多租户模型不在本轮改造范围。

## 6. 接口设计

REST 风格，由 ABP `CrudAppService` 自动生成前缀 `/api/app/shops`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/app/shops?Keyword=&Category=&IsEnabled=&SkipCount=&MaxResultCount=&Sorting=` | 分页查询（FR-S-01） |
| GET | `/api/app/shops/{id}` | 详情 |
| GET | `/api/app/shops/enabled` | 转盘数据源：仅启用店铺、轻量 DTO（FR-W-01） |
| POST | `/api/app/shops` | 新增（FR-S-02） |
| PUT | `/api/app/shops/{id}` | 修改（FR-S-03） |
| DELETE | `/api/app/shops/{id}` | 软删除（FR-S-04） |

DTO：

- `ShopDto`：列表/详情返回
- `CreateUpdateShopDto`：新增与编辑共用，带数据注解校验
- `EnabledShopDto`：转盘专用（仅 `Id / Name / Category / AveragePrice / Address`）

## 8. 非功能需求

- **国际化**：`en.json` / `zh-Hans.json` 同步维护，禁止硬编码文案；注意修复现有 `zh-Hans.json` 的乱码与孤儿键。
- **兼容性**：Chrome / Edge 最新版；移动端自适应（≥360px 宽）。
- **性能**：转盘首屏接口响应 < 300ms；列表默认每页 20 条。
- **可用性**：所有破坏性操作二次确认；错误提示使用 ABP 统一异常与本地化文案。
- **数据安全**：删除为软删除；权限不足时跳转登录或显示 403。

## 9. 验收标准（P0）

1. 管理员可在 `/shops` 完成店铺的新增、编辑、删除、停用，刷新后数据正确。
2. 必填项为空或名称超长时，前端给出明确校验提示，接口返回 400 + 本地化错误。
3. 访客访问 `/` 或记录页面跳转登录，业务接口拒绝匿名请求；登录但无店铺管理权限仍可抽取和查看本人记录，访问 `/shops` 被拦截。
4. 主页转盘扇区与"启用店铺"完全一致；停用一家后刷新，该扇区消失。
5. 点击开始 → 动画 4~6 秒 → 停止在某扇区 → 弹窗结果与指针所指扇区一致。
6. 无启用店铺时显示空状态，不白屏、不报错。
7. 连续快速点击"开始"不会触发多次抽取。
8. 附近搜索勾选若干结果后点"加入本次转盘"：这些门店**追加**到现有转盘（门店库门店仍在），再次加入继续累加且不重复；点"清空附近候选"后转盘回到纯门店库候选。
9. 附近搜索结果能翻到第 2 页及以后，"下一页/上一页"按真实总数正确启用禁用；总页数与总数显示正确。
10. 点"使用当前位置"定位不准时，可点"恢复默认位置"回到默认中心；"设为默认位置"后刷新页面仍以该点为中心。
11. `dotnet build LunchFate.slnx` 0 警告 0 错误；`dotnet test LunchFate.slnx` 全绿。
