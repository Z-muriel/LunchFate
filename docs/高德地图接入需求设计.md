---

## 1. 背景与目标

LunchFate 当前已具备店铺 CRUD 与午餐大转盘能力。为支撑 P2 规划的"按距离筛选"、提升管理员维护效率、改善用户体验，需接入高德 Web 服务 API。

**目标**：在现有 ABP 分层架构下新建 `Integration` 层，封装所有外部地图服务调用，提供六项地图相关能力，且**外部服务不可用时主流程不受影响**。

**不做**：订餐、支付、外卖对接（与需求文档红线一致）。

## 3. 详细需求

### 3.1 FR-M-01 地理编码（地址 → 经纬度）

**功能描述**：将店铺地址文本转换为 GCJ-02 坐标系经纬度，存储于 `Shop` 聚合根。

**触发时机**：
- 新增/编辑店铺保存时，若地址发生变更，自动调用地理编码。
- 后台任务可对历史数据批量补全（可选，P2）。

**输入**：地址文本（`Shop.Address`，≤256 字符）

**输出**：经度（`Longitude`）、纬度（`Latitude`），精度 6 位小数

**异常与降级**：
| 场景 | 处理 |
|---|---|
| Key 未配置 / 服务关闭 | 跳过地理编码，经纬度留空，不阻断保存 |
| 高德返回非 1（失败） | 记录警告日志，经纬度留空，不阻断保存 |
| 超时（>3s） | 同上 |
| 地址为空 | 不调用，经纬度清空 |

**缓存**：以地址文本哈希为 Key，内存缓存 24 小时，避免重复调用。

---

### 3.2 FR-M-02 按距离筛选/排序店铺

**功能描述**：用户授权浏览器定位后，店铺列表支持"距我最近"排序；转盘可限定"只抽附近 N 公里"。

**输入**：用户当前位置（纬度、经度）、筛选半径（默认 3km）

**输出**：店铺列表按距离升序；或启用店铺集合过滤为半径内子集

**异常与降级**：
| 场景 | 处理 |
|---|---|
| 用户拒绝定位 | 使用 IP 定位（高德 IP API）兜底，失败则不显示距离 |
| 店铺无经纬度 | 排在列表末尾，不剔除 |
| 距离服务异常 | 回退到默认排序（更新时间倒序） |

---

### 3.3 FR-M-03 一键导航到店

**功能描述**：转盘结果弹窗提供"去导航"按钮，跳转高德导航页面。

**实现方式**：前端拼接高德 URI API，**无需后端调用**：
```
https://uri.amap.com/navigation?to={经度},{纬度},{店铺名}&mode=walking&src=lunchfate
```

**输入**：店铺经纬度 + 名称

**输出**：浏览器打开高德导航页

**异常与降级**：
| 场景 | 处理 |
|---|---|
| 店铺无经纬度 | 隐藏"去导航"按钮，或降级为展示地址文本 |

---

### 3.4 FR-M-04 POI 搜索（辅助新建店铺 / 加入转盘）

**功能描述**（v1.1 与实现对齐）：登录用户在首页或店铺页输入关键字，调高德周边搜索返回候选列表（支持分页浏览），勾选后可：

1. **加入本次转盘**（首页）：**追加**到当前转盘，不清空已有候选。转盘候选 = 门店库启用门店 ∪ 已加入的附近门店，按 POI 标识去重；转盘上另提供"清空附近候选"回到纯门店库候选。抽取记录会按获胜者标记"临时附近门店"并保留 POI 标识。
2. **批量写入店铺库**（店铺页）：批量新增门店，单条独立事务，同名跳过、其余继续；POI 自带坐标原样带入门店库，避免地址解析偏差。

> v1.0 描述的"选中后回填新增表单"未采用：改为"加入转盘 / 批量入库"两条独立路径，避免把 POI 结果与手工表单校验混在一起。

**输入**：关键字（≤80 字符，可为空）、搜索中心经纬度、半径（100~50000 米）、页码与每页条数（1~25，高德 `offset` 上限）

**输出**：分页的 POI 候选（名称、地址、电话、评分、经纬度、距搜索中心距离升序），以及**真实匹配总数**（用于总页数）

**搜索中心**：
- 初始中心取服务端配置 `Integration:Gaode:Default*`；
- "使用当前位置"用浏览器定位覆盖（定位精度取决于浏览器/系统，室内常偏差几百米，故必须提供回退手段）；
- "设为默认位置"把当前中心写入浏览器 `localStorage`，下次打开优先于服务端配置；
- "恢复默认位置"清除本地覆盖并回到服务端配置的默认中心。

**异常与降级**：
| 场景 | 处理 |
|---|---|
| 搜索失败 / 服务未启用 | 返回空页，页面提示"附近没有找到匹配的店铺" |
| 分页参数非法 | 服务端抛 `UserFriendlyException`，不静默夹取 |
| 后续页为空 | 提示"没有更多结果了"（高德 `count` 声明数可能大于实际可返回数） |
| 浏览器拒绝定位 | 提示"无法获取当前位置，请检查浏览器的定位权限"，搜索中心保持不变 |

**权限**：仅要求登录（`[Authorize]`）。批量写入门店库另需 `LunchFate.Shops.Default` + `LunchFate.Shops.Create` 两项权限，前端入口用同一条件判定。

---

### 3.5 FR-M-05 天气提示

**功能描述**：首页显示当日天气，雨雪天文案引导"选近的店"。

**输入**：城市编码（高德 `adcode`，默认北京 110000）

**输出`：天气现象、温度、风力

**异常与降级**：
| 场景 | 处理 |
|---|---|
| 服务不可用 | 隐藏天气区域，不影响转盘 |

---

### 3.6 FR-M-06 地图可视化标点

**功能描述**：店铺详情抽屉或列表页嵌入高德 JS API 地图，展示店铺位置标点。

**输入**：店铺经纬度 + 名称

**输出**：交互式地图（标点 + 信息窗口）

**异常与降级**：
| 场景 | 处理 |
|---|---|
| JS API Key 未配置 | 隐藏地图区域，显示地址文本 |
| 店铺无经纬度 | 不打标点 |

## 4. Integration 层设计

### 4.1 项目结构

```
src/LunchFate.Integration/
├── LunchFate.Integration.csproj
├── LunchFateIntegrationModule.cs        # ABP Module，注册 HttpClient + Options
├── Gaode/
│   ├── GaodeMapOptions.cs               # Key、基础 URL、超时、启用开关、证书校验开关、默认搜索中心
│   ├── IGaodeMapService.cs              # 服务接口 + MaxPageSize 常量
│   ├── GaodeMapService.cs               # HttpClient 实现
│   ├── GaodeResponse.cs                 # 高德统一响应封装
│   ├── GeocodeResult.cs                 # 地理编码结果 DTO
│   ├── PoiSearchResult.cs               # 周边搜索结果项 DTO
│   ├── PoiSearchPage.cs                 # 周边搜索单页结果（Items + TotalCount）
│   └── WeatherResult.cs                 # 天气结果 DTO
```

### 4.2 接口定义（与实现一致）

```csharp
public interface IGaodeMapService
{
    /// <summary>周边搜索单页可返回的最大条数（/v3/place/around 的 offset 上限）。</summary>
    public const int MaxPageSize = 25;

    /// <summary>地理编码：地址 → 经纬度。失败返回 null。</summary>
    Task<GeocodeResult?> GeocodeAsync(string address, string? city = null, CancellationToken cancellationToken = default);

    /// <summary>周边搜索：结果按距离升序，TotalCount 为真实匹配总数，可直接用于分页。失败返回空页。</summary>
    Task<PoiSearchPage> SearchAroundAsync(
        string keywords,
        double longitude,
        double latitude,
        int radius,
        int pageNum = 1,
        int pageSize = MaxPageSize,
        CancellationToken cancellationToken = default);

    /// <summary>查询城市实时天气。失败返回 null。</summary>
    Task<WeatherResult?> GetWeatherAsync(string adcode, CancellationToken cancellationToken = default);

    /// <summary>计算两坐标间直线距离（米），Haversine。</summary>
    double CalculateDistance(double lat1, double lng1, double lat2, double lng2);
}
```

> **为什么用 v3 而不是 v5**：v5 的 `/v5/place/text`、`/v5/place/around` 的 `count` 字段返回的是**本页条数**（实测每页都等于 `page_size`），前端据此算出的总页数恒为 1，"下一页"永远不可点；`/v3/place/around` 的 `count` 是真实匹配总数，且响应直接带 `distance`，`sortrule=distance` 还能保证跨页全局按距离升序。集成层已对总数缺失的情况回退为"至少这么多、可能还有下一页"，避免同类问题再次把翻页按钮禁用。

对外应用服务是 `LunchFate.Maps.MapAppService`（不是 v1.0 写的 `GaodeAppService`）：`GetWeatherAsync` / `GetDefaultLocationAsync` / `SearchNearbyAsync` / `CalculateDistanceAsync`，全部 `[Authorize]`，内部只依赖 `IGaodeMapService`，不直接碰 `HttpClient`。

### 4.3 配置（三处，缺一处就有功能静默失效）

```jsonc
// 1) src/LunchFate.Blazor/appsettings.secrets.json（gitignored，模板见 appsettings.secrets.json.example）
{ "Integration": { "Gaode": { "Key": "<Web 服务 Key>" } } }

// 2) src/LunchFate.Blazor/appsettings.json（服务端渲染读取）
// 3) src/LunchFate.Blazor.Client/wwwroot/appsettings.json（WASM 渲染读取，2 与 3 必须一致）
"Integration": {
  "Gaode": {
    "BaseUrl": "https://restapi.amap.com",
    "TimeoutSeconds": 3,
    "Enabled": true,
    "AllowInvalidServerCertificate": false,
    "JsApiKey": "<Web端(JS API) Key>",
    "SecurityJsCode": "",
    "DefaultLongitude": 113.293333,
    "DefaultLatitude": 23.092112,
    "DefaultLocationName": "中山大学广州校区南校园"
  }
}
```

- `Key` 为空时 `IsEnabled()` 返回 false，所有服务端调用直接返回 `null`，不发 HTTP 请求。
- 服务端 `Key` 与前端 `JsApiKey` 是两种不同用途的 Key，不能互换。
- `SecurityJsCode` 仅对 2021-12-02 之后申请的 JS Key 必需（缺失会报 `INVALID_USER_SCODE`）。
- `AllowInvalidServerCertificate` 默认 `false`；打开即关闭 TLS 校验，仅限本机调试。
- `Default*` 是附近搜索的初始中心，由 `MapAppService.GetDefaultLocationAsync` 下发给前端；只需配在服务端（`LunchFate.Blazor/appsettings.json`），浏览器可用 `localStorage` 覆盖，避免两套客户端配置不同步。

### 4.4 降级策略

- 所有方法 `try-catch` 包裹，异常时返回 `null`/空集合，**绝不抛出**阻断业务。
- `Enabled = false` 或 `Key` 为空时，直接返回 `null`，不发 HTTP 请求。
- 地理编码结果内存缓存 24h（`IMemoryCache`，Key 为地址哈希）。
- 前端地图：`ShopMap` 组件把渲染失败原因 `console.warn` 出来，页面降级为地址/坐标文本并给出 `Map:RenderFailed` 提示，**不再静默吞异常**。

## 5. 数据模型变更

`Shop` 聚合根新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `Longitude` | `double?` | 经度（GCJ-02），可空 |
| `Latitude` | `double?` | 纬度（GCJ-02），可空 |

对应 EF 迁移：`20261010103432_AddShopCoordinates`。
同批次还有 `20261012031240_AddActivityRecords`（抽取记录 / 门店添加记录快照表），见 `docs/需求文档.md` §5。

**地理编码触发时机（FR-M-01 的实现口径）**：

| 场景 | 行为 |
|---|---|
| 新增且未提供坐标 | 按地址解析；解析失败或未配置 Key → 坐标留空 |
| 新增且客户端提供了 POI 坐标 | 直接采信，不调用地理编码（FR-M-04） |
| 编辑且地址变化、未提供坐标 | 重新解析 |
| 编辑且地址未变化 | 不调用地理编码，坐标保持 |
| 编辑且地址被清空 | 坐标清空（避免导航指向旧地址） |
| 只提供经度或纬度其一 | 视为无效，按地址解析 |

## 7. 验收标准

1. 无 Key 或 Key 错误时，系统正常启动，转盘主流程不受影响。
2. 店铺保存后，地址成功转为经纬度（高德返回成功时）；**编辑改地址同样会重新解析**（回归用例 `EfCoreShopGeocodeTests`）。
3. POI 搜索返回分页候选列表，**可翻到第 2 页及以后且总页数正确**；勾选后可加入转盘（追加、去重、不覆盖门店库候选）或批量写入门店库，且写入的门店带有坐标。
4. "去导航"按钮正确跳转高德导航页（`mode=walk`、`callnative=1`）。
5. 外部 API 超时/异常时，页面显示降级提示，不白屏。
6. 首页与店铺页的嵌入地图均能渲染出瓦片与标点（需 `JsApiKey` 在服务端与客户端两份配置中同时存在）。
7. 搜索中心可"使用当前位置"、"设为默认位置"（刷新后仍生效）、"恢复默认位置"。
8. `dotnet build LunchFate.slnx` 0 警告 0 错误；`dotnet test LunchFate.slnx --no-build` 全绿。
